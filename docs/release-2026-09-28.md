# Photos and responsiveness release — 2026-09-28

This release includes paged Photos and Library browsing, background preview
preparation, resource-aware preview limits, foreground preview memory priority,
nonblocking login loading, catalog session reuse, and per-manifest zstd encoder
reuse. It also includes the Takeout conflict fixes already running on production.
R5/R6 remain partial: node-wide retained-metadata memory admission, adaptive
pressure feedback, owner fairness, PGO and large-host throughput gates are open.

## Validation

- Full `make check`: Go tests, race tests, vet, line limits and JavaScript syntax.
- Fresh-image container smokes with Restic and shared storage, including restart
  readbacks and a disposable Restic-to-shared migration.
- Recovery smoke: restore, login, unlock, original readback and archive cleanup.
- Chromium smoke on 2 CPUs / 4 GiB: Photos paging, preparation failures/retry,
  albums, thumbnails, music artwork/playback, Library controls, floating uploads,
  viewport overflow, restart and owner isolation.

The first GitHub run exposed a timing-dependent migration fixture: two concurrent
uploads did not always enter the same 35 ms batch. The fixture now explicitly
creates one real Restic snapshot with two catalog references, preserving the
migration assertions without relying on scheduler timing. Production batching is
unchanged.

These use disposable data and do not establish production scaling gains. The
release image retains Go 1.25 and Restic 0.18.0 from the existing Dockerfile;
the local host's toolchain and codec microbenchmarks are recorded separately in
the [responsiveness workbook](../responsiveness_workbook_2026-09-28.md).

## Production preflight

The Takeout watcher reached `complete` at 07:00 UTC on September 28. Its report
records 95,476 files, 717.81 GiB logical data, 55.89 GiB exact-file savings and
643.95 GiB of physical Restic repository allocation. No corrupt entries or
unreadable archives were reported. Three ZIPs remained under historical review
holds (149.40 GiB total). Following the owner's explicit cleanup instruction,
all three were reverified against current library entries, sampled SHA-256
readbacks and deterministic conflict mappings. Private audit records remain on
the host; source deletion follows successful deployment validation.

Production's Compose file and bind mounts must be preserved. A stopped XFS
copy-on-write snapshot supplies a local rollback point without duplicating the
encrypted repository blocks. It is not an independent off-host backup. Preserve
the previous image and host source modifications alongside that snapshot.
