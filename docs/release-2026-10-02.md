# Photos selection release — October 2, 2026

Photos now has hover selection circles and persistent touch selectors. After
selecting one photo, clicking tiles toggles their selection instead of opening
the viewer. Shift-click selects a loaded range; Escape or Clear ends selection.
The selection toolbar stays clear of the date rail on desktop and mobile.

Bulk Archive/Unarchive and Hide/Unhide use encrypted, owner-, visibility- and
revision-bound server selections. Every selected revision is validated before
one encrypted catalog save. A stale selection cannot partially hide a batch.
Hide includes paired motion components. Original bytes, paths, identities and
album membership are retained.

Archive removes photos from the ordinary timeline. Hidden photos are excluded
from normal Photos views, search, album memberships/covers, detail, thumbnail,
original and new grab/export requests. Hidden browsing uses an explicit context.
Library still exposes the owner's files; Hidden is not a separate password
boundary. Existing frozen grab capsules keep their sealed copies. Unhiding a
photo cannot override a hidden ancestor folder; restore that folder first.

The API keeps `action: archive` for download ZIP preparation. Bulk photo archive
flags use `set_archived`/`unarchive`; visibility uses `hide`/`unhide` and returns
an `updated` primary-photo count. See [the Photos API](photo-api.md).

## Verification and deployment

The feature and subsequent selection fixes were deployed as application image
`weazlcloud:release-813d258`. Source revision `e3d5ae0` adds only an album test
cleanup fix; it does not require a production container restart.

Full local checks passed. Disposable 2-CPU/4-GiB browser smokes on Restic and
shared-store backends cover selection, Archive/Hidden restore and original
retention. Further targeted browser checks cover deselection and mobile date-rail
clearance. Live HTTPS desktop and touch checks exercise selectors, bulk action
availability, Escape, normal viewing and mobile overflow without mutating photos.
The [final application CI run](https://github.com/bprendie/weazlcloud/actions/runs/37000868608)
passed checks, browser and container jobs.

Two older test fixtures were corrected: concurrent cache writes may refuse
admission when all available capacity is pinned; album tests drain background
work before deleting their temporary vaults. Cache admission checks passed 50
race-detector runs, and album cleanup passed 20.

Production reconciliation preserved 96,971 Library entries, 37,082 photos,
16 albums, capture dates and three sampled original hashes. Existing vaults,
settings, resource limits, storage backend and manually paused preparation state
were preserved. Consistent checkpoints were retained before image changes.

## Compose packaging

The accompanying Compose update supports one configurable image tag for both
services, a selectable data bind mount, and documented preview environment
settings. Automatic admission remains the default when optional values are
absent; the sidecar retains its one-CPU/2-GiB default and network isolation.
See the [Compose guide](docker-compose.md) and
[environment example](../deploy/compose.env.example). This packaging update does
not replace an existing host's runtime override or change its vault mounts.
